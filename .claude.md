# ARGUS — Claude Code Instructions

---

# Identity

Project: ARGUS

ARGUS is a professional Secure Code Review Platform built with Django.

Its long-term objective is to become an enterprise-grade Application Security (AppSec) platform capable of helping developers identify, understand, prioritize, and remediate security vulnerabilities throughout the software development lifecycle.

The platform emphasizes:

- Accuracy
- Security
- Performance
- Maintainability
- Scalability
- Developer Experience
- Professional UI/UX

---

# Core Principles

Always prioritize:

1. Security
2. Clean Architecture
3. Maintainability
4. Readability
5. Modularity
6. Extensibility
7. Performance
8. Consistency

Never sacrifice architecture for visual polish or implementation speed.

---

# Development Philosophy

Development is incremental.

Every task should:

- preserve existing functionality
- leave the project in a working state
- modify only what is required
- avoid unrelated refactoring
- improve maintainability where appropriate

Never rewrite large portions of the project unless explicitly instructed.

---

# Current Workflow

For every prompt:

1. Inspect the current implementation.
2. Explain the intended implementation strategy.
3. List every file that will be modified.
4. Wait for approval if more than two files require modification.
5. Implement only the requested feature.
6. Verify the implementation.
7. Stop.

Never continue into another sprint automatically.

---

# Git Workflow

Always work on feature branches.

Never commit directly to `main`.

One sprint = One commit.

Use Conventional Commits.

Examples:

- feat(...)
- fix(...)
- refactor(...)
- style(...)
- docs(...)
- test(...)
- chore(...)

---

# Architecture Principles

ARGUS follows a modular architecture.

Prefer:

- reusable components
- isolated services
- low coupling
- high cohesion
- dependency isolation
- clear separation of responsibilities

Avoid:

- duplicated logic
- monolithic modules
- tight coupling
- feature-specific hacks

---

# Backend Rules

Prefer service modules over large Django views.

Avoid modifying:

- settings.py
- urls.py
- models.py
- migrations/

unless explicitly requested.

Preserve public APIs whenever possible.

---

# Frontend Rules

Preserve responsive layouts.

Prefer improving existing components over redesigning pages.

Use reusable styles instead of page-specific CSS.

Keep JavaScript modular.

Avoid unnecessary client-side complexity.

---

# Design System

ARGUS uses the **Midnight Slate** design language.

Characteristics:

- Professional
- Enterprise
- Calm
- Minimal
- Modern
- Developer-focused

Avoid:

- Pure black
- Neon colors
- Heavy gradients
- Glassmorphism
- Hacker aesthetics
- Excessive animations

Prefer:

- subtle borders
- restrained shadows
- clean spacing
- reusable design tokens
- consistent typography
- accessible contrast
- visual consistency

---

# UI Consistency

Maintain a consistent design language across the platform.

Avoid:

- one-off component styling
- hardcoded colors
- inconsistent spacing
- inconsistent typography
- duplicated CSS

Prefer:

- shared components
- reusable utility classes
- design tokens
- consistent spacing scale

---

# Scan Experience

Long-running operations should always provide meaningful feedback.

Prefer:

- progress bars
- engine-by-engine status
- estimated progress
- incremental updates
- completion notifications
- clear error states

Avoid:

- unexplained loading screens
- indefinite spinners
- page reloads for progress updates
- blocking the interface unnecessarily

---

# Security Principles

Never introduce:

- SQL Injection
- Command Injection
- Path Traversal
- Unsafe Deserialization
- Broken Access Control
- Weak Cryptography
- Cross-Site Scripting (XSS)
- Cross-Site Request Forgery (CSRF)

Validate all external input.

Follow secure coding practices.

---

# Performance

Avoid:

- repeated database queries
- repeated file parsing
- duplicated AST traversal
- unnecessary object creation

Prefer:

- efficient algorithms
- reusable caches where appropriate
- scalable implementations

Do not redesign the architecture solely for optimization.

---

# Code Quality

Follow PEP 8.

Prefer:

- small focused functions
- reusable classes
- composition
- descriptive naming

Avoid:

- dead code
- duplicated logic
- oversized functions
- magic numbers

Remove obsolete code when appropriate.

---

# Testing

Every completed sprint should include verification.

Verify:

- Django starts successfully
- No Python errors
- No template errors
- Existing scans continue working
- Existing reports generate successfully
- Dashboard remains functional
- Authentication and authorization remain intact
- Responsive layout is preserved
- Accessibility is maintained
- Existing integrations continue working

---

# Documentation

Whenever a completed sprint changes architecture, workflow, project status, or user-facing functionality, update:

- README.md
- PROJECT.md
- ROADMAP.md
- TODO.md

Keep documentation synchronized with the implemented state of the project.

---

# Task Scope

Implement only what is requested.

Do not:

- redesign unrelated pages
- begin future phases
- introduce speculative features
- perform unrelated refactoring

Stop after completing the requested work.

---

# Completion Checklist

Before considering a sprint complete:

- Implementation finished
- Code reviewed
- Verification completed
- Documentation updated (if required)
- Working tree clean
- Ready for commit

---

# Stop Rule

After verification:

1. Summarize completed work.
2. List modified files.
3. Report verification results.
4. Stop.

Never begin the next sprint without an explicit prompt.

# Long-Term Vision

ARGUS should evolve into a professional Application Security platform comparable in engineering quality—not feature parity—to products such as:

- GitHub Advanced Security
- SonarQube
- Snyk
- Semgrep

Future capabilities include:

- Static Application Security Testing (SAST)
- Dependency Analysis
- Secret Detection
- Repository Exploration
- AI-assisted Security Guidance
- Professional Reporting
- Enterprise Features

Every contribution should move ARGUS toward that vision while preserving clean architecture, maintainability, and a polished developer experience.
