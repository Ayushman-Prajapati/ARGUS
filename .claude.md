# ARGUS — Claude Code Instructions

---

# Identity

Project: ARGUS

ARGUS is a professional Secure Code Review Platform built with Django.

Its long-term objective is to become an enterprise-grade Application Security (AppSec) platform capable of helping developers identify, understand, prioritize, and remediate security vulnerabilities.

The platform emphasizes:

- Accuracy
- Security
- Performance
- Maintainability
- Developer Experience
- Professional UI/UX

---

# Core Principles

Always prioritize:

1. Security
2. Clean Architecture
3. Maintainability
4. Readability
5. Modularity
6. Extensibility
7. Performance

Never sacrifice architecture for visual polish or speed of implementation.

---

# Development Philosophy

Development is incremental.

Every task should:

- preserve existing functionality
- leave the project in a working state
- modify only what is required
- avoid unrelated refactoring

Never rewrite large parts of the project unless explicitly instructed.

---

# Current Workflow

For every prompt:

1. Inspect the current implementation.
2. Explain the intended changes.
3. List every file that will be modified.
4. Wait for approval if more than two files will change.
5. Implement only the requested feature.
6. Verify.
7. Stop.

Never continue into another sprint automatically.

---

# Git Workflow

Always work on feature branches.

Never commit directly to `main`.

One sprint = One commit.

Commit messages should follow Conventional Commits.

Examples:

feat(...)
fix(...)
refactor(...)
style(...)
docs(...)
chore(...)

---

# Architecture Principles

ARGUS follows a modular architecture.

Prefer:

- reusable components
- isolated services
- low coupling
- high cohesion
- clear separation of responsibilities

Avoid:

- duplicated logic
- monolithic modules
- tight coupling

---

# Backend Rules

Prefer service modules over large Django views.

Avoid modifying:

- settings.py
- urls.py
- models.py
- migrations/

unless explicitly requested.

Preserve public APIs whenever possible.

---

# Frontend Rules

Preserve responsive layouts.

Prefer improving existing components over redesigning pages.

Use reusable styles instead of page-specific CSS.

Do not introduce unnecessary JavaScript.

---

# Design System

ARGUS uses the **Midnight Slate** design language.

Characteristics:

- Professional
- Enterprise
- Calm
- Minimal
- Modern
- Developer-focused

Avoid:

- Pure black
- Neon colors
- Heavy gradients
- Glassmorphism
- Hacker aesthetics

Prefer:

- subtle borders
- restrained shadows
- clean spacing
- consistent typography
- reusable design tokens

---

# Security Principles

Never introduce:

- SQL Injection
- Command Injection
- Path Traversal
- Unsafe Deserialization
- Broken Access Control
- Weak Cryptography

Validate all external input.

Follow secure coding practices.

---

# Code Quality

Follow PEP 8.

Keep functions focused.

Prefer composition over duplication.

Keep modules maintainable.

Remove dead code where appropriate.

---

# Testing

Every completed sprint should include verification.

Verify:

- Django starts
- No Python errors
- No template errors
- Existing functionality preserved
- Responsive layout preserved
- Existing integrations continue working

---

# Documentation

Keep documentation synchronized.

Whenever a major feature is completed, update:

- README.md
- PROJECT.md
- ROADMAP.md
- TODO.md

if the implementation changes them.

---

# Task Scope

Implement only what is requested.

Do not:

- redesign unrelated pages
- begin future phases
- introduce new features
- perform speculative refactoring

Stop after completing the requested work.

---

# Long-Term Vision

ARGUS should evolve into a professional Application Security platform comparable in engineering quality—not feature parity—to products such as:

- GitHub Advanced Security
- SonarQube
- Snyk

Every contribution should move the project toward that vision while preserving clean architecture and maintainability.
